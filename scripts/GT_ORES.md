# 普通 GT 矿基础设施

本模块接入本地 GTM 参考中 80 种有 `.ore(...)`、没有 `.gem(...)` 的普通矿物。不注册粉末，不接入 GT 大矿脉、机器或化学处理。

## 原版 GT5 矿石补充

`ModOres.EXTRA_ORDINARY` / `ModOres.EXTRA_GEM_ORES` 记录 [原版 GT5 5.07.07](https://github.com/GregTech6/GregTech5/releases/tag/v7.10.50707) 中 List 缺少的 99 种矿石材料。79 种掉原矿，20 种掉普通品质宝石，并沿用五档宝石换算。全部使用现有的十七种宿主和对应工具、掉落与贴图。

13 种在原版 GT5 有生成定义的材料使用 List 的宿主分布和 50% 尝试过滤。其余 86 种矿块和掉落物可在杂项栏取得。普通矿补充目前提供原矿，宝石补充提供品质换算配方。

## 物品与掉落

- 原版铁、铜、金原矿和红石沿用原版物品与矿石生成，不重复注册矿块。
- 其余 76 种矿物各注册一份原矿，共 76 个物品。
- 20 种实际具有 GT 锭属性的金属输出中，铁、铜、金锭沿用原版，其余 17 种锭由普通矿物体系统一注册。
- 已移除旧 `ModItems` 中的铝锭、硅岩锭单独注册及其手工创造栏条目；统一使用 `list:aluminium_ingot` 和 `list:naquadah_ingot`，均采用 GT 分层贴图。
- 铁粒、金粒沿用原版；新增 18 种粒，包括铜粒、铝粒、硅岩粒。
- 所有新物品堆叠 64。除不可破坏、无掉落的基岩矿外，普通挖掘掉原矿，时运增加产量，精准采集掉矿石，爆炸衰减保留。
- 有 GT 直接冶炼目标但目标没有锭属性的材料不编造锭。例如菱镁矿保留原矿，暂不熔炼为镁。
- 原版红石仅复用，不新增粉末注册。没有金属冶炼目标的矿砂和非金属矿目前只提供原矿，供以后增加用途。

## 生成与资源

76 种矿物各有石头、深板岩、花岗岩、闪长岩、安山岩、凝灰岩、方解石、下界岩、末地石、砂岩、沙砾、沙子、红沙、红砂岩、玄武岩、黑石、基岩十七种矿块，共 1292 个。与已有宝石矿共用 `OreHost`；常规宿主使用原版 `Feature.ORE` 和精确基底替换，基岩使用原版单点 `SimpleBlockFeature`。

主世界：石头 Y=0..64、深板岩 Y=-64..-1、花岗岩/闪长岩/安山岩 Y=-64..64、凝灰岩 Y=-64..0、方解石 Y=-64..256；每种每区块尝试 1 次，矿团大小 4。

下界：下界岩、玄武岩、黑石 Y=8..120；末地：末地石 Y=0..96。两者每种每区块尝试 2 次，矿团大小 6。每个基底只注入对应维度群系。此为轻量统一分布，并非 GT 原版材料分区。

新增砂岩、沙砾、沙子、红沙、红砂岩均在主世界 Y=-64..256 生成，只替换同名原版方块，原始矿团大小 4、每区块尝试 1 次。沙砾、沙子、红沙矿均为原版 `FallingBlock` 重力方块，失去支撑并收到更新后下落，使用铲子标签，其余使用镐子标签，均保持铁级工具门槛。

基岩矿在主世界和下界的世界底部之上第 1～4 层进行单点尝试，只匹配原版基岩。使用相对底部高度，且不扩散矿团，因此绝不替换最底层基岩。硬度 -1、抗爆 3600000、无掉落，并加入凋灵与末影龙免疫标签；生存模式不可采掘。基岩每区块尝试 1 次，继续经过 50% 过滤。

所有自定义矿石（普通矿和宝石矿、所有维度）每次尝试均经 50% 放行过滤器。`rarity_filter` 位于 `count` 之后，`chance=2`，所以主世界每种配置平均尝试 0.5 次/区块，常规下界和末地矿平均 1 次，基岩在主世界和下界均平均 0.5 次；原有矿团大小、掉落和原版矿石生成不变。新增宿主会扩大生成覆盖范围，减半的是每种配置的尝试放行率，不保证实际总矿块数恰好为旧版一半。

模型沿用 GT 图标集颜色与继承资源，PNG 与实际来源的 `.png.mcmeta` 一起导入，来源和 SHA256 记录在纹理清单中。新内容追加到杂项栏的已有宝石矿之后。

原矿、锭、粒与矿石补 Forge 通用/材料标签。铝同时提供 `aluminium` 与 `aluminum` 锭粒标签。

## 配方与代码接口

35 种新增矿有实际金属冶炼目标，每种提供熔炉（200 tick）和高炉（100 tick）配方，产出 1 锭；原矿与矿块均可输入（基岩矿不提供采集掉落），共 70 个冶炼配方。为可玩性采用轻量直接冶炼，未模拟 GT 高炉温度、气体和机器等级。

18 种新增粒提供 3×3 粒合成 1 锭和 1 锭分解 9 粒，共 36 个配方。铁与金复用原版配方。合计 106 个新配方。

- `ModOres.ORE_MATERIALS` / `.METAL_MATERIALS` 是声明目录。
- `ModOres.raw(id)` / `.ingot(id)` / `.nugget(id)` 查询物品；必须在注册完成后解析。
- `ModOres.ores()` 查询普通矿块。
- `OreHost.register(...)` 将材料名称、颜色、覆盖层和掉落接入所有矿石资源与维度生成。

## 维护与验证

从项目根目录运行：

```powershell
python scripts/gt_normal_materials.py
python scripts/import_gt_ore_textures.py
$env:JAVA_HOME = 'D:\Java\jdk21'
$env:GRADLE_USER_HOME = 'D:\document\dev\gradle\.gradle'
.\gradlew.bat --no-daemon runData
python scripts/verify_gt_gems.py
python scripts/verify_gt_ores.py
.\gradlew.bat --no-daemon compileJava processResources build
python scripts/verify_gt_ores.py --jar build/libs/list-3.0.7.jar
```

本环境 `runData` 存在 provider 和 HashCache 保存后 JVM 不退出的问题；必须确认所有 provider 完成、HashCache 已保存、生成验证通过后，才能终止本次明确识别的 data JVM。由此产生的退出码 1 不代表 Gradle 正常成功，最终独立 build 仍需通过。
